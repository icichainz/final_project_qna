Query decomposition with per-document retrieval quotas

Comparative follow-ups — "which of those has the largest budget?" — are N independent questions wearing one trenchcoat. This feature splits them into per-entity sub-queries, retrieves inside each target document, and hands the answering model a context where every candidate is actually represented. It implements the "Query decomposition + grouped retrieval — Adopt" item of the retrieval roadmap.

1 · The failure this fixes

Observed twice in live testing (at TOP_K=5 and again at TOP_K=10):

User: How are indigenous peoples involved in project design and consultation?
Bot: excellent 9-document synthesis…
User: Which of those has the largest dedicated budget?
Bot: "The context excerpts provided do not specify the total budgets…" ← honest, but a dead end

The refusal is correct behavior with the wrong context. The condensation step rewrites the follow-up into one embedding query mentioning several documents at once — and no single point in embedding space is simultaneously close to budget-annex tables in five different documents. The semantically dominant consultation pages win every slot, the budget tables never enter the context, and no TOP_K fixes a query that should never have been one query.

2 · Design

2.1 Decomposition extends the condensation call

The existing history-condensation call (commit 1f4e310) is upgraded to return JSON — either one standalone query (today's behavior) or, when the message compares/aggregates over specific documents named in the conversation, one sub-query per entity:

{"queries": [
  {"q": "indigenous peoples plan dedicated budget",
   "doc": "40_gcf-b39-02-add11-funding-proposal-package-fp236"},
  {"q": "indigenous peoples planning framework budget",
   "doc": "11_gcf-b42-02-add07-funding-proposal-package-fp265"}
]}

The doc ids come from the previous answers' citations, which are already in the history window. Same single LLM call as before (response_format: json_object), max 6 sub-queries, and any parse failure falls back to the raw message — the feature can only add capability, never break a turn.

2.2 Doc-scoped retrieval new: doc_filter in Retriever.search

For a sub-query tagged with a document, FAISS is searched wide (k≈200) and hits are post-filtered to that document, keeping the top 3. Matching is forgiving (prefix/substring) since the LLM may cite a truncated id. At 186k vectors a wide flat search costs ~10 ms on this machine — the roadmap's "post-filter is trivial at this scale" judgment, verified.

2.3 Merge, label, answer answer path unchanged

Per-entity results are deduplicated, capped at 15 chunks, and grouped under document headers in the context so the model can compare entity-by-entity. Sources, grounding, and highlighted evidence pages flow through the existing machinery untouched. The UI's retrieval query step lists every sub-query, so decomposition is inspectable per turn.

3 · Honesty rules

  • A comparison over entities the user named is a closed set — comparing them fully is legitimate and needs no hedge.
  • If a target document contains no figure, the answer states it: "FP236: US$ X; FP265: no budget figure stated in the document." A partial comparison beats both refusal and invention.
  • The corpus-wide superlative rule (commit 292c2d2) still applies: decomposition compares the named entities, never silently extends claims to all 273 documents.

4 · Cost & limits

First-turn questionsuntouched — no history, no decomposition call
Known limitentity→doc resolution relies on ids cited in history; resolving free-form names ("the Chad proposal") needs the roadmap's metadata registry (stage 2 companion)

5 · Acceptance tests

  • Unit: doc_filter returns only chunks of the target document, top-3 by score.
  • Decomposition: the live model, given the real indigenous-consultation history, emits ≥3 doc-tagged sub-queries as valid JSON.
  • End-to-end (the rematch): the exact transcript that failed twice — indigenous question, then "which of those has the largest dedicated budget?" — produces a per-entity budget comparison (with honest gaps where documents state no figure) instead of a refusal.
  • Regression: a first-turn question and a simple follow-up behave exactly as before.
