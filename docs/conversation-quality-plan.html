Conversation quality: one conductor call, four fixes

Four multi-turn gaps share a single root: the per-turn rewrite call is triggered only sometimes, does only one job, and feeds an English-only embedder from whatever language the user writes. This plan replaces it with one conductor call that runs every turn and decides mode, splits intents, and normalizes language — then slims the system prompt that has accreted around it. Nothing in retrieval, grounding, or persistence changes.

The four items

1

English retrieval queries for any input language highest value

Real users write French; all-mpnet-base-v2 is an English model, so their queries embed poorly and retrieval silently degrades for exactly the primary audience. The conductor always emits English search queries regardless of input language; a one-line prompt rule makes the answer model respond in the user's language. BM25 is unaffected (identifiers are language-neutral).

Measured acceptance: translate the 8 paraphrase gold questions to French → recall@5 with and without the conductor. Expectation: French recall approaches the English 100%; English unchanged.

2

Mode routing: a no-retrieval path small

"Summarize our conversation", "merci !", "what did you just say?" currently trigger retrieval and stuff irrelevant excerpts into context. The conductor returns mode: "chat" for conversational/meta turns → answer directly from history, skip retrieval, sources message, and evidence images entirely.

Acceptance: meta and courtesy messages produce no sources line; corpus questions still retrieve (spot-check that ambiguous cases fail open — when unsure, retrieve).

3

Multi-intent splitting, first turn included small

Today decomposition splits only comparisons, and only when history exists — your three-questions-in-one first message diluted per-document retrieval. The conductor runs every turn and may emit up to 6 queries for any multi-question message. All existing guards carry over verbatim: message-named identifiers override tags, fabricated tags are stripped, empty filters degrade unscoped.

Acceptance: the transcript's 3-part message answers all three parts (FP274 figure, FP218 → UNEP via registry, FP270 results); single questions behave identically to today.

4

Conditional system-prompt assembly risk reduction

The system prompt has accreted ~9 rule groups; we measured (three iterations of the year rules) that gpt-4o-mini drops procedural rules in long prompts. Split it into blocks assembled per turn: core (identity, grounding, honesty — always) + year block (only when a year note exists) + registry block (only when a Registry line is present) + comparison block (only on multi-query turns) + language rule (always). Typical turns carry roughly half the current prompt; every rule ships only alongside its trigger.

Acceptance: re-run the four canonical transcript scenarios (budget chain, temporal, superlative probe, comparison) — same or better answers; log the assembled prompt length per scenario.

The conductor contract

{"mode": "retrieve" | "chat",
 "queries": [{"q": "<standalone ENGLISH search query>", "doc": "<id or null>"}, ...]}  // ≤6, retrieve mode only
  • Runs every turn (first turns included — new). Adds one small LLM call (~300–500 ms) to first turns that previously skipped it; follow-up turns already pay it.
  • Failure falls back exactly as today: mode=retrieve, single query = raw message. The conductor can only add capability, never break a turn.
  • Kill-switch: CONDUCTOR=0 restores the current history-only behavior for A/B.
  • All post-processing guards (id override, fabrication strip, unscoped degrade) apply unchanged.

Verification battery

  • French gold mini-set (new, committed): 8 translated paraphrase questions → recall@5 before/after. The headline number for item 1.
  • English gold set: must hold 100/100/100 with CONDUCTOR=1.
  • Transcript replays: 3-part message, budget-comparison chain, "summarize our conversation", "merci", FP999, superlative probe.
  • Guard unit tests re-run unchanged.
  • Deployment: standard push → rebuild → in-container battery, same as every feature so far.
Definition of done. French paraphrase recall measured and materially improved; English gold set unchanged; meta-turns produce no sources; the 3-part first message answers all parts; assembled prompt ≤ ~60% of current length on plain turns; kill-switch verified; deployed with in-container evidence.
Effort & risk. Roughly one focused day, all inside chainlit_app.py plus a prompt-blocks module and the French mini-set. Main risk is conductor regressions on flows that work today — bounded by the kill-switch, the guards staying in code, and the replay battery. No index, schema, or deployment changes.
