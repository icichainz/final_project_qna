RAG correctness: next implementation steps

The retrieval foundation now finds the intended document reliably. This plan moves the system from document recall to evidence-complete, conflict-aware, and verifiable answers.

Objective. Every factual answer should be traceable through a stable chain: resolved document, requested field or section, retrieved evidence, generated claim, and exact page citation. Missing or contradictory evidence must remain visible rather than being guessed away.

Target architecture

Question→Identifier + field planner→Registry / hybrid candidates→Rerank + section expansion→Evidence matrix→Answer→Claim verifier

History is available to the planner for resolving follow-ups, but only current-turn evidence is available to the factual answer and verifier.

Scope and decisions

DecisionReason
Keep hybrid FAISS + FTS5 retrievalIt already reaches 100% document recall on the current gold set.
Do not change embeddings firstPage-level and answer-level labels are needed to prove that a model migration helps.
Do not build GraphRAG nowThe current failures concern canonical fields, page selection, and support verification rather than global graph traversal.
Preserve source text separatelySection prefixes can improve retrieval, but grounding must continue matching the original extracted page text.
Use deterministic checks before LLM judgesIdentifiers, currencies, arithmetic, field coverage, and citation presence can be checked exactly and cheaply.

Implementation sequence

0

Freeze an answer-level baseline First

Turn the complex manual probes into reproducible fixtures before changing answer behavior.

  • Expand to 50-80 cases covering exact IDs, compact IDs, semantic discovery, comparisons, contradictions, French, noisy input, and nonexistent proposals.
  • Label expected documents, exact evidence pages, required fields, expected calculations, and whether the correct behavior is answer, conflict, or abstention.
  • Record the current answer and retrieval outputs so later improvements are attributable.

Touchpoints: scripts/gold_set.jsonl, a new answer fixture file, and a new end-to-end evaluation script.

Gate: current 100% document recall must remain the retrieval floor.

1

Isolate answer evidence from conversation history Low risk

Continue using history in the conductor, but stop passing prior assistant answers into factual generation. The answer call receives the latest question, resolved references, and current retrieved evidence only.

  • Keep chat-mode behavior unchanged for conversational turns.
  • Represent resolved follow-up entities as a small trusted note instead of replaying old answers.
  • Add a regression where FP220 is asked after unrelated FP254/FP248 turns.

Touchpoints: src/gcf_qna/app/chainlit_app.py, src/gcf_qna/app/prompts.py.

Gate: changing preceding conversation must not change a fully specified factual answer.

2

Upgrade the registry to provenance-aware facts Core

Move canonical proposal fields out of probabilistic chunk selection while retaining every source candidate.

  • Cover title, phase, countries, accredited entity, A.5-A.11, instruments, direct/indirect beneficiaries, implementation period, and Board code.
  • Parse templated headings deterministically first; use an extraction model only as a fallback.
  • Keep raw text, normalized value, unit, currency, page, section, and status.
  • Calculate or rank only compatible units and currencies.

Touchpoints: scripts/build_registry.py, src/gcf_qna/rag/registry.py, data/registry.json schema version 2.

Gate: FP274 and FP275 canonical fields reproduce labelled pages exactly and expose known conflicts.

3

Add section-aware retrieval and reranking Core

Improve precision within an already-correct document without breaking the grounded viewer.

  • Store source_text, retrieval_text, section_path, page, and table identity separately.
  • Keep markdown tables atomic where practical and attach their heading path to retrieval_text.
  • Hybrid-retrieve a wider candidate pool, deduplicate before quotas, rerank query-passage pairs, then expand selected evidence to its parent section or neighboring page.
  • Ground citations against source_text, never the added retrieval prefix.
  • A/B the existing embedder and a modern multilingual model only after this page-level baseline exists.

Touchpoints: src/gcf_qna/rag/chunk.py, src/gcf_qna/rag/index.py, src/gcf_qna/rag/retrieve.py, src/gcf_qna/rag/ground.py, scripts/build_index.py.

Gate: required evidence-page recall improves without reducing document recall; grounding highlights remain visually correct.

4

Plan comparisons as document by field matrices Coverage

Use deterministic planning whenever the question names documents and known fields; reserve the LLM conductor for semantic decomposition.

  • Resolve every explicit FP and Board code before retrieval.
  • Create one job per requested document and field, with a guaranteed evidence quota.
  • Build an evidence matrix before prose generation and mark each cell as stated, calculated, missing, or contradictory.
  • Require all cells to be addressed before the answer is accepted.

Touchpoints: a small planner module under src/gcf_qna/rag/, plus chainlit_app.py and prompt assembly.

Gate: FP254/FP228/FP248 returns all three rows, refuses cross-currency ranking without a conversion rule, and never starves the last document.

5

Verify claims and repair once Trust

Validate the generated answer at atomic-claim level before displaying it.

  • Extract factual claims and their cited document/page pairs.
  • Classify each as supported, contradicted, or unsupported by the cited evidence.
  • Run one constrained repair pass that may remove, qualify, or replace claims but may not introduce new sources.
  • If required claims remain unsupported, answer partially or abstain.
  • Display only sources actually cited by the final verified answer.

Touchpoints: a verifier module under src/gcf_qna/rag/, chainlit_app.py, and claim-level tests.

Gate: zero unsupported claims in the labelled high-risk set; citation precision at least 95% before broader rollout.

6

Roll out behind independent switches Adopt

Measure each layer independently instead of shipping a single opaque pipeline change.

  • Suggested switches: structured facts, reranking, section expansion, answer verification, and factual-history isolation.
  • Report document recall, page recall, required-field coverage, numerical accuracy, conflict detection, abstention, citation precision, latency, and model cost.
  • Keep the existing hybrid path as the fallback until the new path clears every correctness gate.

Gate: no regression in current retrieval classes and material improvement on the complex answer suite.

Deferred options

Vision verification for difficult tables, whole-document long-context reading, agentic search, a modern embedding model, and GraphRAG remain valid experiments. None should enter the default path until the answer-level harness identifies a gap that the core plan cannot close.

Definition of done. The ten complex probes and the expanded gold suite return complete, page-grounded answers; contradictions are surfaced; incompatible currencies are not ranked; nonexistent identifiers abstain without unrelated sources; and every displayed factual claim is supported by its cited evidence.
