GCF Q&A Build Report

How a directory of 46 loose files, six forked apps, and a crashing extraction script became a grounded question-answering system over 41,550 pages of Green Climate Fund proposals — with page-cited answers, highlighted evidence images, per-document comparative retrieval, and a claim verifier calibrated against blind human adjudication. The system

What exists now

Four ingest stages communicating through disk, a grounding layer that ties every answer back to pixels on a page, and — after the correctness campaign — an answer path of its own: conductor, deterministic planner, provenance-aware registry, and a claim verifier that grades the answer before its sources are shown.

The answer path, in one sentence. A question either builds a deterministic evidence matrix from the registry (the planner, when it names two or more identifiers and a known field) or goes through an LLM conductor that emits a mode and English sub-queries; tag guards resolve document references through the registry; section-aware hybrid retrieval returns evidence in 65 ms; the factual answer call receives a system prompt and one user turn and no conversation history, with resolved references arriving as a registry-built note; and a claim verifier re-checks every factual claim against the evidence the turn actually held before any source is displayed. Each layer sits behind its own switch, so each was measured on its own rather than as one opaque pipeline change.

Act II

Re-architecture: one package, one truth per constant

Every mess in the old tree was the same mess — forking a file instead of parameterizing it. Six near-identical apps existed because config was hardcoded per copy.

Two incidents, reported as they happened

Leaked credentials. Five live API keys (Anthropic, Google, HuggingFace, 2× OpenAI) sat hardcoded in source and notebook outputs — and the old git history containing them was pushed to a public GitHub remote. They were scrubbed from all files and both are absent from the new history; revocation of the old keys remains the only real fix and stays on the owner's list. Git deletion. During setup, an rm intended for a scratch repo executed in the wrong working directory and deleted the project's local .git. Working files were never touched; the full 11-commit history was later recovered from the GitHub remote and preserved on the legacy-pre-rearchitecture branch. The new history was started fresh by explicit owner decision.

Act III

Grounding: answers that point at pixels

Built for three uses: cited-passage highlighting in a viewer, grounding RAG citations to page regions, and table/figure localization — all from the born-digital PDFs' own text layer, zero OCR.

Geometry sidecars. The render pass (and a one-time backfill over 273 cached PDFs, 63 min) wrote page_NNNN.boxes.json beside every page JPEG: text-line rectangles from get_text("dict"), table regions from find_tables(), figure regions from image rects and clustered vector drawings — all in pixel coordinates of the cached image. 41,500 sidecars, 262 MB, 100% of tracked pages. Two corpus-specific fixes came from eyeballing real output: span-union line rects with a font-size height cap (dotted ToC leaders inflated boxes), and keeping large drawing clusters inside tables (GCF templates nest charts in page-wide tables — Figure 6 of FP275 was being discarded as table ruling).

Page-aware chunks. Chunking runs within page boundaries, so every index entry carries {doc_id, page, text} and the app cites [doc, p. 17]. Verified: 243/243 pages parse contiguously from a real merged document.

Fuzzy alignment. The chunk text is VLM-written markdown; the boxes text is the PDF text layer — they never match verbatim. ground_chunk() token-matches chunk against lines (≥60% line coverage → highlight rect), routes table-dominant chunks to detected table regions, and degrades to an honest page-level citation below 0.3 confidence. Measured on live retrievals: prose confidence 0.96–1.00, with VLM-dropped running headers correctly left unhighlighted.

The viewer. Each chat answer attaches up to three evidence images — the cited page with green line-highlights or a blue table region, rendered server-side with PIL and cached by rect-hash. The proof was visual: real pages with exactly the cited grievance-redress passages boxed, surrounding text clean.

Index & serving

Embedding 186,802 chunks — CPU vs GPU (all-mpnet-base-v2, same corpus)

Serving fixes, each measured: the retriever (730 MB index + embedder) now loads once per process in a background thread at boot and is shared across all chat sessions — previously each session re-read it and the first question paid ~60 s. The registry became provenance-aware. Every canonical field now carries its raw source text, normalized value, currency, page, and section — 3,785 candidates across 273 documents, parsed deterministically from the template headings in 18 seconds, every raw string verified as a literal substring of its cited page. The corpus turned out to disagree with itself constantly: 120 documents carry at least one genuine internal financing conflict (FP274 prints three different GCF figures on pages 7, 8 and 40). The system now surfaces these with page citations instead of picking one silently.

Each wave was reviewed before it was committed — and every review caught something the tests could not. Wave 1's reviewer found a stale duplicate of the identifier regex that would have hard-scoped year-like tokens to wrong documents, and year notes claiming contiguous FP ranges that were false for 4 of 11 years. Wave 2's found the pre-scoping guard starving pronoun comparisons. Wave 3's replayed 24 recorded production answers through the new verifier and measured an 18% false-positive rate — driven by citation style, not wrong answers — which would have made a repair pass rewrite correct answers. That sample was fixed and re-measured at zero false positives, and it is cited here as history only: the artifact was never checked in and cannot be re-run, so the campaign that follows replaced it with a reproducible measurement over all 165 recorded claims against human-adjudicated gold. The honest answer, when it arrived, was far worse than 18%.

What was live at the end of this chapter: everything measured — pre-scoping, history isolation, section-aware retrieval with the mention-magnet fix, the healed registries — plus PLANNER=1 (deterministic evidence matrices) and VERIFY=1 in observation mode: warnings render, answer rewrites stay off. Whether those rewrites should ever have been switched on is the subject of Act X; the answer turned out to be no, and the pathway was deleted rather than left behind a flag.

Act VII · the campaign

Answer correctness as its own program

Retrieval was finished: 30/30 document recall@5 on the gold set, MRR 1.00. So the first full deterministic measurement of the answers was allowed to be as bad as it turned out to be — and it was.

The number that started it. release-1 (66 cases, 19 Aug, recorded and checksummed) scored 94 supported / 165 claims = 57.0% deterministic claim support against a ≥95% release gate, with 71 failures (23 contradicted + 48 unsupported; by kind: money 34, entity 29, year 5, existence 2, number 1), required-field coverage 54/56, p50 3.4 s / p95 8.3 s, ≈$0.33 per run. Groundedness was not measured at all — the record's hits carried {doc, page, score} with no text, so no groundedness figure existed and none could be derived by hand. The plan says so in those words rather than quoting a number it could not reconstruct.

The plan the campaign executed (docs/rag-correctness-next-steps.html) is seven ordered steps, each with its own gate: 0 freeze an answer-level baseline before changing answer behaviour; 1 isolate answer evidence from conversation history; 2 upgrade the registry to provenance-aware facts; 3 add section-aware retrieval and reranking; 4 plan comparisons as document×field matrices; 5 verify claims at atomic-claim level; 6 roll out behind independent switches. Steps 0–4 are the pipeline above. Steps 5–6 are everything that follows.

The execution plan (docs/claim-support-execution-plan.md, 554 lines) sequenced the work into waves −1 through 5 under one rule: nothing lands unreviewed, no matcher change is justified by inference, no measurement change is booked as an improvement, and no eval activity can reach production by accident. It opened by finding that it could not safely start: a 1,008-line uncommitted, unreviewed agent wave sat in the working tree, and make push / make deploy rsync the working tree, not a commit. Those 235 unreviewed verify.py lines were deployable that day, on the live VERIFY=1 path. Wave −1 exists to close that before any other work starts.

The metric contract, stated before any number was collected

Every claim metric is published as n/d, never as a bare rate — in gate output, in the dashboard, and in this report. A rate whose denominator moved is not a comparison. Gates are integer counts, not rounded percentages: the ≥95% gates print n/d plus the exact threshold ceil(0.95 × d). And because extract_claims decides the claim population while a repair pass could rewrite answers, every gate additionally requires the absolute supported count to be non-decreasing and every claim present before and absent after listed with its status and a written justification — not only the supported ones. Deleting 63 unsupportable sentences and fixing 63 produce the same headline; only the denominator discipline tells them apart.

Act VIII · the instrument

Measuring the measurer

A verifier that grades answers is itself an instrument, and an uncalibrated instrument produces confident nonsense. Most of the campaign was spent proving what this one could and could not see.

What it is. The verifier is a pure detector: it splits an answer into atomic claims with their cited document/page pairs, classifies each against the evidence the turn actually held using deterministic matchers (money with unit and currency guards, entities with alias rules, years, existence, numbers), and refers only the residue — unsupported and plausible — to an LLM judge. Verdicts are supported, contradicted or unsupported; they drive the caution banner and the source list. It never writes. Since e38a75d that is structural rather than configured: verify_answer has no repair parameter, its .answer is always the text it was given, and no status is ever repaired.

The judge, audited rather than trusted. Wave 3 reported supported (140) exceeding grounded (139) at the parity baseline, which reads as the judge accepting claims nothing supports. Audited claim by claim against the evidence each turn held: zero of the 28 promotions is a fabrication. All 11 the matcher had flagged were its own brittleness — 7 surface-form (a coined acronym, a possessive with a curly apostrophe, a composite entity the extractor glued together), 2 cross-lingual, 1 a negated term counted as asserted, 1 an outside-knowledge gloss. The judge is discriminating: a 68% accept rate, 13 reasoned rejections of which 12 were grounded elsewhere but not in the cited scope, and it produced the run's only contradicted verdict by demoting a claim the matcher had missed. Turning it off would mislabel 21 of 66 answers and put an abstain banner on 9 correct ones. Recorded against it in the same commit, plainly: one promotion used a full name appearing nowhere in held evidence — harmless in that run, but a live mechanism. The recommendation was to keep the judge and fix the matcher, which the next commit did: five artifact classes, each traceable to audited row ids, each pinned by a widen harness (18 mutations, 0 unpinned); the judge's residue shrank 41 → 34 candidates.

Five arms, because four were blind. The adjudicated gold holds only claims the release flagged, so recall over it is pinned at 100% by construction — it measures the instrument, not the code, and a change that only ever stops flagging things cannot fail there. Three further arms were added and two reviews then showed them still blind exactly where relaxations live. The scorer therefore carries five arms, reported separately and combined, none of which ever consults a verdict:

The blind spot that justified the fifth arm

The merge review of the calibrated verifier replaced _field_conflict with return None — deleting every evidence-text contradiction the verifier can emit — and the four-arm report did not move: gold 30.8%, overall 73.1%, all four matrices identical to the count, the caution census identical. Two independent causes: the census counted flags on supported claims only, while the conflict flags are emitted solely on contradicted branches; and the 66 recorded answers contain zero contradicted verdicts, so on their own they can never witness that path however they are filtered. The fifth arm is 34 seeded rows over 12 cases and 8 documents in four shapes, 21 of which promote to supported when the path is broken rather than merely degrading — which is what finally moves a cell. Ten ablations: 8 detected, 2 named as still invisible and pinned by tests that fail if they ever become visible.

The calibration itself. Five review rounds rejected the calibration diff; each time the pattern was a relaxation that closed its reported case and opened a wider one. The round that landed kept only what survived adversarial attack and deleted the rest — with its cost stated: registry_settled (read registry silence as a ruling, earned 0 rows), acronym pairing (its two-way substring defeated 51/51 indexed acronyms, 2 rows), scoped_absences (excused a name because it was absent — the condition selects for fabrications, 4 rows), registry_absence (4 rows), containment dedup (1 row), board-token widening (3 rows). Fourteen adjudicated false positives therefore stay flagged: a deliberate trade, recorded as one. Gold-arm precision 16.9% → 30.8%; after the extractor fix that retired heading-form units, 40.0%, with the gold arm's false flags falling 59 → 27 → 15.

Act IX · adjudication

Blind labelling, and what it cost the verifier

The methodological centre of the campaign. A verifier cannot be calibrated against its own opinions, and an agent that builds a matcher must not be the sole judge of which of its outputs were wrong.

The instrument is blinded. Handing a labeller the verifier's own status and reason — "not found in the cited evidence: X" — and then asking whether the verifier was wrong builds the verifier's priors into the reference standard. The anchoring suppresses verifier_false_positive rows from ever being proposed, which no amount of owner spot-checking on the FP rows can repair. So the export carries only the question, the full answer, the claim text, its citations, and the text of the evidence the turn actually held; status, reason and kind are stripped. The labeller answers "is this claim entailed by the held evidence — yes / no / ambiguous?" plus a cause, knowing nothing of what the verifier concluded. Verdicts are joined back afterwards to derive true and false positives.

The taxonomy was written before labelling, so the rulings are not reverse-engineered from whichever labels the rows happened to attract. Each row records two independent fields — verifier_correct (should this have been flagged at all?) and root_cause (which component has to change?) — because conflating them is precisely what made "false positive" carry two meanings at once. Eight labels, and four rulings on the contested shapes: colon lead-ins and markdown headings are not_a_claim (the fix belongs in extraction, and teaching the matcher to support half-sentences would be the wrong component changing); closed-world negatives are supported where the registry confirms the absence, scoped narrowly to existence and nothing else; a bracket pointing at a page the turn never held is wrong_citation, not missing_citation, because the answer did cite.

The gold set contains negatives. Adjudicating only the 71 flagged claims would make the calibration gate's "recall == 1.000" mean "do not un-flag failures you already caught" and say nothing about false negatives — supported claims that are actually wrong. Every calibration hunk is a relaxation, and relaxations produce false negatives. So a seeded stratified sample of ≥40 of the 94 supported claims was labelled through the same blinded instrument, interleaved, with no indication of which rows had been flagged.

Owner adoption is a signed commit, not a string field. The anti-circularity mechanism cannot be a free-text reviewer value inside a file that both the labelling agent and the tooling agent can write. The owner reviews 100% of verifier_false_positive rows (the only label that authorises a code change), 100% of ambiguous_unscorable rows, and a seeded stratified 20% of every other bucket, then commits the sign-off GPG-signed, touching nothing else. Agents cannot produce a signed commit. Downstream, every calibration hunk carries an Adjudicated-anchors: git trailer and a checker refuses any commit touching verify.py whose trailer names a key that is absent or not labelled a false positive. A held-out slice was sealed before any hunk was written, because gating on the same anchors a fix was mapped to is a fit statistic dressed as a validation statistic.

What the false positives authorised, by mechanism: 14 registry-conflict figures the system's own note prints (the answer obeyed "report both figures with their pages" and was penalised for it), 14 doc-level or cover-page citations, 7 exact-value matches on held evidence, 7 registry-confirmed closed-world negatives, 3 acronym / full-name pairs. The stricter reading was available and was rejected for a stated reason: treating coarse-but-correct citation as a verifier hit pushes generation toward citing a specific page it never held, and an invented page reads as precision. The residue the protocol left visible rather than tidied

Two of the 12 genuine defects are colon lead-ins textually identical in form to a row that was re-resolved to not_a_claim when the inter-rater disagreements were settled. They were never sampled, so the frozen gold keeps the stale label. Since the extractor change their units are no longer minted as standalone claims and their checkable content is verified through the blocks they ride on. Scored defects are therefore 10 + 2 resolved, the gold file is left frozen, and re-resolution awaits an owner spot-check. The alternative — quietly editing the anchor everything downstream is measured against — was not available.

Act X · the refutation

The feature that passed every metric and was killed

Step 5 of the plan called for "one constrained repair pass" that may remove, qualify or replace claims. It was built, gated, attacked, re-measured, and then deleted — because the measurement said so.

The A/B was designed so only repair could differ. Two fresh generations of the same pinned config share just 11 of 66 answers — ≈83% resampling — so a generated A/B confounds the repair effect with generation variance. The wave therefore replayed one recorded answer set through the verifier twice, with the repair pass on and off, and scored it twice more: once with the carry of pre-repair judge rulings disabled and a fresh classification over the rewritten text, once as production would have shipped it. The gate is the carry-off number; the carry-on number is reported as the production-behaviour figure. Certifying a rewrite with a judge opinion formed on the pre-rewrite text is the self-certification pattern the plan forbids elsewhere.

But the finding that decided it was not a threshold. Repair is not a fixed quantity. From the same answers and the same verdict objects, the adoption decision flipped on 18–27% of cases, and two full replays disagreed on whether repair had corrected 5 claims or deleted 7 — because the rewrite call sent no temperature and no seed, so every rewrite of user-visible text was an unpinned sample. Concretely: a 351-character registry-backed abstention became the single word "None." (the anti-gutting guard cannot fire when the count of supported required claims is already zero, which is exactly the population repair is invoked on); an English answer was rewritten into French in 2 of 3 samples and adopted both times; and the pass systematically attacked conflict-reporting answers — the ones most valuable to a reviewer — by prefixing a denial while keeping the contradicted content, which scores 1.0 on every check in the suite.

The engineering answer was a suite written blind to the implementation. Three blocking prerequisites were implemented, and then tested by an agent that wrote its tests from the specification — commit 52152af's findings — before and independently of the code, so they could not inherit the implementer's blind spots. Thirty-six tests over four gates. It scored 35/36, and the one failure was a pre-existing hole deliberately left open and recorded as an executable xfail rather than a comment. Then the last verification hole was closed as a design pass rather than the patch three reviewers had proposed three incompatible versions of. The invariant was stated before the code was written: a verdict may not answer supported on a scope it has not conflict-tested. Every branch that mints a supported verdict now passes one shared per-key, field-anchored gate, and an AST check pins the shape so a new support branch cannot appear without either calling the gate or breaking that equality visibly. The blind attack suite went 36/36 — its page-repoint attack, written by an agent that never saw this code, flipped from xfail to pass — the contradicted arm went 33/34 → 34/34, exactly one of 343 scored rows changed status, and 0 of 132 live answers moved.

With the gates in place and an extractor veto removed, repair finally acted — and the verdict became decisive rather than another deferral. Adoption rose from 0/11 to 3/7 and 1/6 on the same frozen input. Three of the five adopted rewrites deleted verified, cited, grounded content: the $55.0M figure documenting FP220's disagreement with the registry, carrying its own caution flag, and "Friday, October 29, 2021" — one of the three board dates the user had asked for — twice, from different completions. One adoption was a genuine, reproducible correction. And the conflict-flattening rewrite was the only completion that reproduced byte-identically across both replays: the most reproducible thing repair does is the harm.

Why every guard passed it, and why that is the point

Zero-remaining-failures (the survivor verifies), anti-gutting (3→2 claims, not →0: the guard fires only when every supported required claim vanishes), the substance floor, the language gate, the invented-source scan — all pass; the answer's own checks read pass: true before and after. Only the offline audit's lost-supported gate saw it. And the gated metrics reward the deletion: support rate, groundedness and citation completeness all rise on that answer. A canary optimising those numbers reads the harm as improvement. The root cause is structural, not sampling: under an adopt-if-clean gate, the cheapest way to satisfy "no claim left failing" is to delete the failing claim and, collaterally, whatever contradicts it — and the answers with the most deletable material are exactly the conflict-reporting ones. Adding the obvious per-claim gate would reject the harms and take adoption back to ~one case per 66 answers, a value indistinguishable from the no-op a wave was spent escaping.

The decision, and its proof. Wave 5 was cancelled and the adoption path deleted rather than switched off — a flag holding a pathway shut is still a pathway. The gate this deletion had to pass, and did: production ran the switch at 0, so removing the pass may change nothing observable. All 66 recorded answers of two release runs replay through the old and new code byte-identically — 396 answer-runs, same output SHA, compared down to every verdict field, source, caution and model-call signature — the five-arm report is byte-identical including its seeded repaired arm, and the app's message stream for a production-config turn is unchanged under a golden test. The one string that would have differed, the recorded "repair disabled" note, is frozen verbatim with the reason written next to it. Tests moved with the code rather than around it: 33 repair-only tests deleted, 15 dual-purpose ones keeping their detector half, and the blind attack suite retriaged 36 → 17 with every retirement named in its header alongside the commit the full suite runs green at. The A/B history stays auditable: the recorded replay and audit artifacts for every run remain in data/eval with their checksums, and the auditor's reading half still reads them.

What is left open, and said so: a repair surfaced as a suggestion beside the answer, never substituted for it, would have put that one genuine correction in front of a human without giving a gate the authority to delete cited content. It is documented future work and a new design pass, not a flag flip — nothing in this tree is waiting to be re-enabled. Recorded, not fixed: with the adoption gate gone, a truncated document id is now indistinguishable from an invented one at the detector; the attack suite pins that fact and an owner ruling on rebuilding the check detector-side is the open item.

Act XI · release

Citations at the sentence, and the final numbers

With the verifier calibrated and frozen, one acceptance gate was still red — and three independent audits agreed the defect was in how answers were written, not in how they were graded.

The diagnosis. On the re-scored release-2 answers, citation completeness stood at 144/165 = 87.3% against the ≥95% gate, with groundedness 89.1%. The dominant failure was a factual sentence carrying no bracket at all. Since the instrument was calibrated against human gold and deliberately frozen, the fix belonged where the defect was: in generation. The change is prompts only.

The rules were written against what the verifier actually measures, not against taste. Sentences inherit a trailing paragraph bracket but bullets and table rows never inherit a sibling's — the exact shape of the adjudicated missing_citation rows — so every list item now carries its own citation. A paragraph's single bracket mis-scopes when its sentences read from different pages, so: cite at the sentence. A hedge is glue to the extractor and honestly leaves the claim denominator, so cite-or-hedge is worded in the phrasings the refusal regex recognises, in both languages. Registry and matrix facts carry the page their own line prints. And when a page is uncertain the document id survives and the page is dropped, never the reverse — an invented page reads as precision. Forty-five tests pin the dimensions, including a 5,000-character prompt budget that turns the module's measured rule-dropping into a tripwire: a new rule either displaces an old one or ships behind its own trigger.

Act XII · operations

What is running, and how it can be undone

A measurement campaign is only worth its artifacts if the artifacts survive, and a release is only worth its gates if the thing deployed is the thing measured.

SHA-tagged images and a real rollback target. The compose file pins image: fp-gcf:${GIT_SHA:-latest}, so every deploy builds a new tag rather than overwriting one. The previous release stays on disk and restarts without a rebuild. Before this change every deploy overwrote :latest with no retained predecessor — the ledger's log therefore starts empty by design, because releases that predate it left no rollback target on the host. The ledger itself answers exactly two questions during an incident, without SSH: which commit is live, and which commit to roll back to. A row is a fact about the past; a bad deploy is corrected by adding the row for the rollback, never by editing the row for the release that broke.

Those three rows keep VERIFY_REPAIR=0 in their switch column because it was true when they were written. From the next deploy on the column drops it: the commit that removed the repair pathway also removed the variable, and a flag nothing reads is a switch that no longer exists. The rows are not edited to match the present — that is the whole point of an append-only ledger.

Interlocks, each written against a demonstrated footgun. push refuses a dirty tree and refuses a HEAD that is not a deploy tag; it greps the remote environment for the keys the stack needs and aborts if any is missing. Evaluation data, canary logs and scratch files are excluded from the rsync, while .env is never excluded — it is how switches reach production, and an exclusion would silently strand every future flip. The index and registry are not excluded either, because production loads them; the index footgun is handled by a loud warning and a refusal to overwrite without an explicit force. The measurement anchor is protected in both directions: the recorded release files are force-added to git despite the data directory being ignored, their checksums are tracked in the same commit, and the recorder refuses to overwrite an existing path. Sixty-seven recorded eval artifacts are checksummed in data/eval/CHECKSUMS.sha256, with the reason written at the top of the file: the baseline run cannot be rebuilt, because re-running it calls the model 66 more times and is a different sample.

The deploy row is pasted by hand, on purpose. make deploy prints the row after the remote docker compose up -d returns; the operator commits it with the next change. Writing it automatically would have the target edit a tracked file mid-deploy, which then trips its own dirty-tree interlock on the following run or forces an unreviewed auto-commit.

Stated honestly: the parity level of the final run

release-3 records its own pipeline parity as partial: deployment-drift, not full. Two reasons, both in the record: the deployment fingerprint file was never captured (an owner action that was not performed), so the deployed switches are read from the tracked ledger row and the local environment rather than from the host, and the remote artifact hashes were not read; and the harness tree (85a9ff7) is ahead of the deployed commit (22f558b) under src/. The number is what it is — the run is production-configured and not production-verified, and the record says which.

Verification

What "verified" meant here

Nothing above rests on inspection alone. The resolution trade-off was benchmarked against the live VLM server; the concurrency crash was reproduced twice from a healthy state before being called real; grounding quality was judged by looking at the rendered highlight images, which caught two geometry bugs no unit test would have; the retrieval iterations were each validated by re-running the exact transcript that failed; and the final budget-comparison answer was accepted only when it produced real figures with per-document honesty. Where a claim could not be verified (corpus-wide superlatives from a sample), the system was taught to say so rather than the report pretending otherwise.

The correctness campaign made those instincts into rules, and the rules are why its numbers can be read as evidence rather than as claims:

No self-certification. No agent certifies its own output and no component certifies itself — the verifier is scored against human gold it never saw, the repair gates were attacked by a suite written from the specification by an agent that never read the implementation, and the headline repair number is the one computed without carrying forward the judge's rulings on the unrepaired text.

Tests pin fixed behaviour in both directions. Every relaxation gets an adversarial negative and a regression pin on the permissive side. This rule exists because twelve held tests pinned only the strict direction, which is exactly how two live regressions survived them.

A gate line whose expectation lives in a comment is not a gate. Each wave's gate block runs verbatim under set -euo pipefail; a non-zero exit or an out-of-tolerance number blocks the commit, and there is no narrative override. Where a change ships behind a switch, the off-path output is proven byte-identical to the pre-change path on a fixed fixture rather than asserted.

Spread before significance. Run-to-run variation was measured and published before the improvement runs — claim-support varies 8.9 pp deterministic and 4.6 pp production on its own — so most per-gap movements were reported indeterminate rather than passed. Two measurement changes that looked like improvements were labelled as measurement: a definition change worth +26 claims, and a parity gap that bought +1.74 pp purely by removing three claims from the denominator, none of them supported.

And the reference standard is blind. The one thing a system cannot do is grade itself; so the 71 recorded failures were labelled with the verifier's own verdict withheld, by labellers who did not know which rows it had flagged, against a taxonomy written before the labelling started, and adopted by a signature no agent can forge.
