The system

What exists now

Four pipeline stages communicating through disk, plus a grounding layer that ties every answer back to pixels on a page.

Act I

Extraction: from crashing script to verified corpus

The inherited extractor rendered pages at 3× the useful resolution, deadlocked on failures, and silently merged incomplete documents. It was rebuilt, measured step by step against the live LM Studio server.

Act II

Re-architecture: one package, one truth per constant

Every mess in the old tree was the same mess — forking a file instead of parameterizing it. Six near-identical apps existed because config was hardcoded per copy.

Two incidents, reported as they happened

Leaked credentials. Five live API keys (Anthropic, Google, HuggingFace, 2× OpenAI) sat hardcoded in source and notebook outputs — and the old git history containing them was pushed to a public GitHub remote. They were scrubbed from all files and both are absent from the new history; revocation of the old keys remains the only real fix and stays on the owner's list. Git deletion. During setup, an rm intended for a scratch repo executed in the wrong working directory and deleted the project's local .git. Working files were never touched; the full 11-commit history was later recovered from the GitHub remote and preserved on the legacy-pre-rearchitecture branch. The new history was started fresh by explicit owner decision.

Act III

Grounding: answers that point at pixels

Built for three uses: cited-passage highlighting in a viewer, grounding RAG citations to page regions, and table/figure localization — all from the born-digital PDFs' own text layer, zero OCR.

Geometry sidecars. The render pass (and a one-time backfill over 273 cached PDFs, 63 min) wrote page_NNNN.boxes.json beside every page JPEG: text-line rectangles from get_text("dict"), table regions from find_tables(), figure regions from image rects and clustered vector drawings — all in pixel coordinates of the cached image. 41,500 sidecars, 262 MB, 100% of tracked pages. Two corpus-specific fixes came from eyeballing real output: span-union line rects with a font-size height cap (dotted ToC leaders inflated boxes), and keeping large drawing clusters inside tables (GCF templates nest charts in page-wide tables — Figure 6 of FP275 was being discarded as table ruling).

Page-aware chunks. Chunking runs within page boundaries, so every index entry carries {doc_id, page, text} and the app cites [doc, p. 17]. Verified: 243/243 pages parse contiguously from a real merged document.

Fuzzy alignment. The chunk text is VLM-written markdown; the boxes text is the PDF text layer — they never match verbatim. ground_chunk() token-matches chunk against lines (≥60% line coverage → highlight rect), routes table-dominant chunks to detected table regions, and degrades to an honest page-level citation below 0.3 confidence. Measured on live retrievals: prose confidence 0.96–1.00, with VLM-dropped running headers correctly left unhighlighted.

The viewer. Each chat answer attaches up to three evidence images — the cited page with green line-highlights or a blue table region, rendered server-side with PIL and cached by rect-hash. The proof was visual: real pages with exactly the cited grievance-redress passages boxed, surrounding text clean.

Act IV

Index & serving

Embedding 186,802 chunks — CPU vs GPU (all-mpnet-base-v2, same corpus)

Serving fixes, each measured: the retriever (730 MB index + embedder) now loads once per process in a background thread at boot and is shared across all chat sessions — previously each session re-read it and the first question paid ~60 s. Cache-first model loading eliminated HuggingFace revalidation (32 → 0 HTTP requests, cold load 16.7 s → 7.7 s). The chat backend speaks the OpenAI protocol with OPENAI_BASE_URL override, so the same app runs against api.openai.com or a local LM Studio at zero cost.

Verification

What "verified" meant here

Nothing above rests on inspection alone. The resolution trade-off was benchmarked against the live VLM server; the concurrency crash was reproduced twice from a healthy state before being called real; grounding quality was judged by looking at the rendered highlight images, which caught two geometry bugs no unit test would have; the retrieval iterations were each validated by re-running the exact transcript that failed; and the final budget-comparison answer was accepted only when it produced real figures with per-document honesty. Where a claim could not be verified (corpus-wide superlatives from a sample), the system was taught to say so rather than the report pretending otherwise.
